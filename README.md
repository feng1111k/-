# ScreenPersonMonitor 屏幕人物监视工具（截图 / 录屏）

屏幕上一旦有人经过指定位置，就自动把指定区域的画面**截图**或**录屏**保存下来。

支持两种工作模式，运行时二选一：

- **截图模式**：和以前一样，监控区域出现人就保存一张 PNG 截图
- **录屏模式**：监控区域出现人自动开始录制 MP4，人离开、连续 **2 秒**没检测到人后自动停止

---

## 使用流程（点开程序后按提示走四步）

| 步骤 | 操作 |
|---|---|
| **第 1 步** | 弹出文件夹选择框 → 选择保存位置（直接取消 = 保存到程序旁边的 `screenshots` 文件夹） |
| **第 2 步** | 弹出模式选择窗 → 点【截图模式】或【录屏模式】 |
| **第 3 步** | 屏幕变成半透明遮罩 → 拖拽框选**【截图区域】**（截图模式）或**【录屏区域】**（录屏模式）→ 回车确认 |
| **第 4 步** | 再次出现遮罩 → 拖拽框选**【监控区域】**（用来判断有没有人的位置）→ 回车确认 |

框完之后程序自动加载模型并开始监视。

### 两种模式的区别

| | 截图模式 | 录屏模式 |
|---|---|---|
| 触发条件 | 监控区域出现人 | 监控区域出现人 |
| 保存内容 | 截图区域的一张 PNG | 录屏区域的一段 MP4 视频 |
| 什么时候结束 | 立即保存；同一个人停留时按冷却时间重复保存 | 连续 2 秒没检测到人才停止 |
| 文件名 | `person_年月日_时分秒.png` | `record_年月日_时分秒.mp4` |
| 可调参数 | 冷却时间 5 秒 | 20 fps，无人 2 秒停止 |

> **录屏是"检测到人之后才开始录"**，所以画面最开头可能比人出现晚零点几秒。
> 监控区域和录屏区域是互相独立的，可以框不同的位置。
> 录屏不含声音；如果电脑的 OpenCV 缺少 MP4 编码器，会自动改用 MJPG 编码保存成 `.avi`，播放方式一样。

### 预览窗说明（全中文界面）

预览窗顶部有一条很窄的状态条，显示当前状态：

| 显示文字 | 含义 |
|---|---|
| 绿色 `监视中 · 已存 N 张` | 截图模式正常监视中，已保存 N 张截图 |
| 红色 `检测到人 · 正在截图` | 截图模式下监控区域检测到人，正在保存截图 |
| 绿色 `监视中 · 等待出现人 · 已录 N 段` | 录屏模式待机中，已经录过 N 段 |
| 红色 `录制中 · 12.3 秒 · 第 2 段` | 正在录屏，右上角同时亮一个红点 |
| 橙色 `已锁定 · 暂停监视` / `解锁后自动继续` | 屏幕被锁屏（Win+L），系统禁止抓屏，锁定期间暂停；解锁后自动恢复 |
| 检测框上的 `人 87%` | 画面里检测到人的位置和置信度（87% = 0.87） |

> 状态条高度只有 34 像素（画面很小时还会自动缩短甚至不显示），尽量少遮挡监控画面。
> 中文字体使用系统的微软雅黑；万一系统缺字体，界面会自动退回英文，不影响功能。

### 退出方式

**按 Q 或 Esc 退出**（点预览窗右上角的 × 也能退出）。

如果正在录屏，退出时会自动停止并把当前视频文件正常写完。

### 框选时的按键

| 按键 | 作用 |
|---|---|
| 鼠标左键拖拽 | 画选框 |
| 鼠标右键 | 重画 |
| 回车 | 确认这个区域 |
| Esc | 取消，程序退出 |

> 两个区域是**互相独立**的：可以框一个很大的区域用于保存/录制（例如整个门口），
> 再框一个很小的区域用于监控（例如门把手附近），只有监控区域里出现人才会触发。

## 排查问题

程序**不会**在保存文件夹里生成任何日志文件，只往里写截图（`person_*.png`）或视频（`record_*.mp4` / `record_*.avi`）。

- **用源码运行**：运行信息直接打印在控制台。
- **双击打包后的 exe**：不会弹 cmd 黑框；运行日志写到 `%TEMP%\ScreenPersonMonitor\ScreenPersonMonitor.log`，出问题时打开这个文件就能看到完整过程。程序遇到未捕获的错误时会弹窗，并把崩溃日志写到同目录的 `crash_*.log`。

如果出现"有人经过但没截图 / 没录屏"，按下面顺序排查：

| 可能原因 | 现象 | 怎么处理 |
|---|---|---|
| 监控区域没框到人 | 预览窗里没有黄色检测框 | 把监控区域框得更贴近人 |
| 人太小 / 距离太远 | 预览窗有黄色框，但置信度低于 45% | 把监控区域框得更紧，或让人物在画面里更大 |
| 屏幕被锁屏（Win+L） | 预览窗顶部显示橙色 `已锁定 · 暂停监视` | 解锁后自动恢复；想持续监控就别锁屏 |
| 录屏刚开始就结束 | 只在触发瞬间录到一小段 | 检查监控区域里是否一直有人；录屏要连续 2 秒没人（或误检消失）才停 |
| 录屏文件是 `.avi` 而不是 `.mp4` | 保存目录里出现 `record_*.avi` | 正常现象：当前电脑的 OpenCV 没有可用 MP4 编码器，MJPG 自动回退 |
| 录屏里没有人出现的开头 | 视频比人出现晚一点 | 录屏是检测到人之后才启动的，属正常现象 |

> **锁屏（Win+L）后无法抓屏**：Windows 会切到安全桌面，这是系统安全设计，任何普通程序都做不到。
> 程序会自动暂停并在解锁后恢复，不会崩溃；正在录制的视频会先停止保存，避免留下空文件。

如果怀疑程序本身有问题，用下面的诊断命令验证：

```bash
python main_opencv.py --probe-dpi                  # 打印 DPI / 屏幕尺寸
python main_opencv.py --test-detect 图片路径        # 对一张图片跑检测, 看能否识别人
python main_opencv.py --rectest 保存目录 4         # 只测录屏: 全屏录 4 秒并读回校验
python main_opencv.py --selftest 保存目录           # 跳过框选, 监视全屏 30 秒
python main_opencv.py --locktest 保存目录           # 锁屏测试, 监视全屏 120 秒
python main_opencv.py --selftest 保存目录 --mode record   # 自检 + 录屏模式
```

### 生成的文件

| 文件 | 位置 | 说明 |
|---|---|---|
| `person_年月日_时分秒.png` | 你选的保存文件夹 | 截图模式保存的截图 |
| `record_年月日_时分秒.mp4` | 你选的保存文件夹 | 录屏模式保存的视频（编码器不可用时是 `.avi`） |
| `ScreenPersonMonitor.log` | `%TEMP%\ScreenPersonMonitor\` | 打包 exe 的运行日志（源码运行只打印到控制台） |
| `crash_*.log` | `%TEMP%\ScreenPersonMonitor\` | 程序崩溃时自动生成的详细错误日志 |
| `debug_first_frame.png` 等 | `%TEMP%\ScreenPersonMonitor_debug\` | 仅自检/锁屏测试模式下的调试图，正常使用不会生成 |

## 工作原理

- **检测**：YOLOv8n 模型（`yolov8n.pt`），只关心 COCO 类别 0 = person，置信度阈值 0.45
- **抓屏**：`mss`，已开启 DPI 感知（每显示器 v2），高 DPI 缩放/多屏下坐标不偏移
- **框选覆盖层**：tkinter 全屏无边框半透明窗口，坐标与物理像素 1:1 对应
- **截图**：`cv2.imwrite` 存 PNG，文件名 `person_%Y%m%d_%H%M%S.png`，默认冷却 5 秒
- **录屏**：独立的录制线程用自己的 `mss` 实例按 20 fps 抓屏，`cv2.VideoWriter` 编码；
  检测线程只负责发"开始/停止"信号，所以录屏帧率不会被 YOLO 推理拖慢
- **自动停止**：最后一次检测到人之后连续 2 秒没人，就关闭当前视频文件

## 命令行诊断工具

下面这些命令主要给排查问题用，正常使用直接双击 exe 即可：

```bash
python main_opencv.py --probe-dpi                  # 只打印 DPI / 屏幕尺寸信息
python main_opencv.py --test-detect 图片路径        # 对一张图片跑一次检测, 打印原始结果
python main_opencv.py --rectest 保存目录 4         # 录屏链路测试(不加载模型, 录全屏 4 秒)
python main_opencv.py --selftest 保存目录           # 跳过框选, 直接监视全屏 30 秒
python main_opencv.py --locktest 保存目录           # 锁屏测试: 监视全屏 120 秒, 期间可 Win+L 验证
python main_opencv.py --mode record                # 跳过模式选择, 直接进入录屏模式
```

打包后的 exe 也支持这些参数，例如：

```powershell
.\ScreenPersonMonitor.exe --probe-dpi
```

因为没有 cmd 窗口，exe 的这些输出不会显示在屏幕上，而是追加写到
`%TEMP%\ScreenPersonMonitor\ScreenPersonMonitor.log`；运行完打开该文件查看结果。

## 重新打包成 exe

```bash
python -m PyInstaller --noconfirm --clean ScreenPersonMonitor.spec
```

生成的 exe 在 `dist\ScreenPersonMonitor.exe`，单文件、自带 Python 和全部依赖，复制到任何位置双击即可运行，**不会弹出 cmd 黑框**。
打包配置已经包含：

- `console=False`：Windows 图形界面程序，无控制台窗口
- `app.ico`：自定义图标（蓝色人物 + 红色录制点）
- `version_info.txt`：exe 属性里显示的产品名、版本号、说明
- 模型 `yolov8n.pt` 一并打进 exe，不需要额外的模型文件

> 单文件 exe 每次启动会先解压到临时目录，比源码运行慢几秒，属于正常现象。

> **打包注意**：`torchvision` 0.29 的原生扩展是 `_C_stable.pyd` / `image_stable.pyd`，
> 而 PyInstaller 默认只收集 `*.dll` 不收 `*.pyd`。`.spec` 里已经用
> `collect_dynamic_libs('torchvision', search_patterns=['*.pyd', '*.dll'])` 处理好了。
> 如果漏掉，exe 会报 `operator torchvision::nms does not exist`，表现为"有人经过也不截图"。
